fucusy/gomoku-first-move-always-win 基于 Allis (1994)《Searching for Solutions in Games and AI》， 用 C++ 实现，整体是五层结构：

为什么黑棋能必胜

  • 无禁手五子棋已被证明是先手必胜游戏（Allis, 1994）。
  • 取胜的本质是造出双威胁：双四、四三、双活三——对手一步只能挡一个。
  • 本引擎把这三种组合直接写进了单点估值 pointScore()，并由 VCF/VCT 做前向验证： 一旦算出杀棋序列，后续每一步都沿着已证明的取胜路线走。

与原项目的差异（如实说明）

  • 原项目的"必胜"来自离线穷举出的完整解局库（仓库体积 > 50MB，外加 RocksDB），是数学意义上的证明；单个 HTML 文件无法内嵌。
  • 本实现用实时威胁空间搜索达成同样的效果：面对人类棋手，黑棋依靠先手优势 + VCF/VCT 杀棋计算，实战中几乎不会落败。
  • 引擎内置声音性闸门：每一步落子前都验证"白棋是否会立即/强制取胜"，并主动封堵白棋的活三升级链（活三→冲四→活四），因此黑棋绝不主动走入必败分支。自测中黑棋对随机白棋 20/20、对引擎白棋（含随机开局）12/12 全胜，0 负 0 和。
  • 原项目 README 也注明其局限：白棋若在离所有棋子 3 格以外落子，解局库可能失效；本实现没有这个问题，任何位置都会实时计算。
